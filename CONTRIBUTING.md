# Contributing

Open an issue proposing a change before adding major features. Proposals should
state the motivation, affected actors, protocol compatibility, example request
and response, trust boundaries, rejected alternatives and a way to test the
invariant. Security reports that could affect any later real implementation
should be communicated privately to the project maintainers, not posted with
working exploit details or credentials in public issues.

No standardisation body or elected governing board currently approves changes.
Versioned drafts and publicly reviewable pull requests are an initial process,
not a substitute for a future community governance model.
